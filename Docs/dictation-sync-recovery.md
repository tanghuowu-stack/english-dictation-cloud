# 学习数据恢复与同步

已迁移账号以 `dictation_sync_states` 中的版本化快照为同步来源。快照保存实际本机 JSON 学习数据（词库、词条、历史、学习设置、复查状态、单库和合并草稿）；设备的待上传标记、同步时间和错误留在本机。历史关系表保留迁移时的内容和 UUID，不是迁移后新学习变更的同步来源。未迁移账号仍可只读读取旧表，不能用旧数据自动覆盖云端。

## 迁移顺序

1. 先离线备份浏览器和云端，再应用 `20261125113000_lossless_dictation_state.sql`。
2. 对账后，同一事务内只补写已核对的关系行并建立版本 1 快照。没有删除历史数据；只有已建立快照的账号会拒绝旧客户端读写原关系表，避免旧代码上传或拉取不完整数据。
3. 应用 `20261125115500_dictation_sync_owner_guard.sql`，然后部署前端。新写接口要求当前登录账号与预期账号匹配，并在事务中检查预期版本。旧版本、另一个账号或未确认的导入备份不能覆盖云端。
4. 打开网站，使用顶部同步状态验证。新设备无本机学习数据时允许自动还原。如果已有本机数据与云端冲突，两边都会保留；先导出本机数据，核对差异后再使用工具页的显式恢复。

## 验证与回滚

- `npm test`、`npm run build`。`tests/dictation-sync-state.test.cjs` 支持用环境变量 `DICTATION_ROUND_TRIP_FIXTURE` 指向本机原始 JSON，用 `DICTATION_CLOUD_ROUND_TRIP_FIXTURE` 指向真实云端 SQL 导出转为 JSON 后的文件；不要把备份或生产载荷提交到仓库。
- 升级或处理冲突前分别保留本地导出、云端版本化快照和原始关系表导出。显式恢复前也在浏览器保留上一份本机副本。恢复验证应逐 ID 及字段检查，不能只核对数量。
- 前端需要回退时，可先暂停新旧客户端的同步并保留版本化快照；不要为了恢复旧前端而直接删除快照或解除旧端写入保护。旧关系格式无法保留最新草稿和所有学习字段。恢复云端快照应当在备份、逐字段核对并确认之后，以当前版本为前置条件写成新版本，保留审计时间和现有 UUID。
- 保活工作流继续只读取 `supabase_keepalive`，不读取学习数据。
